# Technical Plan: `SPEC-planning-effort-safeguards` Planning effort safeguards

## 1. Architecture Overview & Impact

- Target Area: the `spec` bundle's guidance (skills, workflow body, role contract) and its Living Spec, after the
  strategy layer (workbench) that owns the effort table.
- No Python code changes: the effort table, the plan-intent procedure and the plan-accept request are guidance and
  workflow-body rules. The data the plan-accept request needs already exists: each `worker` envelope carries
  `activity_effort`, and `devkit workflow envelope check --unit <dir>` lists the envelopes by kind.
- Invariants kept: gates, exit checks and `required` policies hold at every effort (`CAP-DLV-delivery-workflows`
  rule 15); effort is run input, never stored; devkit stays SDD-agnostic.
