# Git policy levels

Read this before the first edit of a task and before any Git action, after `devkit spec policy` printed the `[GIT_POLICY: worktree= pull_request= delete_branch= setup=]` line. Decide the worktree and the integration path before the first edit, not after.

- `worktree` applies to `direct` mode only: `local-orchestrated` always runs each worker in a worktree and `cloud-pr` uses the runner's checkout. `worktree=required` runs every `spec` and `proposal` activity (on its `plan-` or `dev-` activity branch) in its own worktree from creation to cleanup ([worktree](worktree.md)); `session` depth is never required to.
- `worktree=auto` leaves it to you: a worktree when the current checkout holds changes unrelated to the task (the user's uncommitted work must stay put), another task is in flight in this checkout, or the user asks; otherwise the current checkout, on the activity branch started with `devkit worktree start <branch> --no-worktree` ([branches](branches.md) §2). Preserve the user's dirty checkout when creating isolation.
- `pull_request=required` integrates every task, `session` depth included, through a PR (no `finish --merge`). `pull_request=auto` uses a PR when the task needs platform review or CI, the base refuses direct pushes, or the user asks; otherwise a local merge.
- The integration path does not choose the worktree: a task integrating through a PR may run on its branch in the current checkout (`--no-worktree`) when no worktree reason applies.
- Report each `auto` choice and its reason in the final change report's assumptions. A request that names the checkout or the integration path overrides the policy for that task and is reported there as a user request; otherwise an unavailable action the policy requires is a blocker, not silently downgraded.
- `delete_branch=yes`: after a confirmed merge, and only under existing deletion authority, the merged task branch is removed with safe `git branch -d` after leaving it (`devkit worktree finish` does this). A dirty worktree, current branch, protected/base branch or unmerged branch prevents cleanup; report the remaining branch. `delete_branch=no` keeps it. This policy never deletes remote branches or forces deletion; an unmerged branch is dropped only by a close (`devkit worktree finish <branch> --discard`, [classification](classification.md) §4).
